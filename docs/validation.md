- 修复手动刷新误报“请求来源无效”：原 `no-referrer` 与来源校验冲突。按 [Fetch 标准的 Origin 生成规则](https://fetch.spec.whatwg.org/#append-a-request-origin-header)，普通表单 POST 在该策略下会发送 `Origin: null`；改为 `strict-origin`，继续隐藏签名路径并保留来源校验。回归测试覆盖同源表单成功跳转，以及 `null`、外站、HTTP 降级、其他子域名仍被拒绝且不刷新二维码。
- 刷新修复部署后，通过正式域名模拟浏览器表单请求：登录页 200 且策略为 `strict-origin`；同源刷新返回 303 并跳回登录页，二维码版本实际变化、新 PNG 返回 200；立即重复刷新返回 429；`Origin: null` 与外站请求仍返回 403。测试未使用真正浏览器驱动；手机重新打开页面后的实际点击效果仍由用户验收。临时 Gotify 测试客户端已删除。

公网验证使用 Android/浏览器风格 User-Agent。Cloudflare 曾对默认 Python urllib User-Agent 返回 403 / 1010；实际 Android 风格 HTTP 请求与浏览器请求已通过，不应将该响应误判为后端二维码生成失败。
